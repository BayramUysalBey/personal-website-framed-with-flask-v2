# **Docker Deployment Bug Report (Containerization of Flask/Postgres)**

This document catalogs the critical system, dependency, and logic errors encountered during the transition of the application from a local virtual environment to a multi-container Docker deployment. These errors represent successful resolution of complex system-level integration problems.

| \# | Error Message | Layer Affected | Root Cause (Why it Failed) | Definitive Solution (How it was Fixed) |
| :---- | :---- | :---- | :---- | :---- |
| **1** | Error: pg\_config executable not found. failed to solve: process "/bin/sh \-c pip install..." did not complete successfully | **Dockerfile / Dependencies** | The original psycopg2 package requires a full **C compiler (pg\_config)** and libraries, which are not present in the lightweight python:3.12-slim image. | Switched the dependency in requirements.txt from psycopg2 to **psycopg2-binary**. This installs a pre-compiled version, eliminating the need for system compilers. |
| **2** | exec ./boot.sh: exec format error | **boot.sh / Operating System** | The boot.sh script, created on a Windows machine, used invisible **Windows line endings (\\r\\n)**. The Linux shell inside the container could not execute the file because it didn't recognize the characters. | 1\. Added the **Shebang Line (\#\!/bin/sh)** to the top of boot.sh. 2\. Added the command **RUN dos2unix boot.sh** to the Dockerfile to automatically clean the file format during the build process. |
| **3** | Database is uninitialized and superuser password is not specified. | **Docker Compose / Postgres Image** | The PostgreSQL image requires explicit environment variables for the main **administrator** user (postgres) during its first startup (initialization). | Added the mandatory variables **POSTGRES\_USER=postgres** and **POSTGRES\_PASSWORD=\<secret\>** to the .env file, satisfying the image's security rule. |
| **4** | FATAL: password authentication failed for user "greeter\_user" | **Docker Networking / Application Code** | The web app was either not receiving the DATABASE\_URL correctly from the .env file, or the password defined in the docker-compose.yml did not match the password the application was trying to use. | Enforced synchronization by removing the hardcoded fallback URL in app.py and ensuring all credentials were loaded securely via a singular **.env** file. |
| **5** | ERROR: relation "counter" does not exist at character 8 | **Application Logic / Timing** | The Flask application attempted to query the counter table **before** the table was created (a common race condition in Docker). | Implemented the **Wait-Init-Start** orchestration in **boot.sh**: The script now uses a Python loop to wait for the database to be *ready* and then explicitly runs the table creation function (create\_tables()) *before* starting the Gunicorn server. |
